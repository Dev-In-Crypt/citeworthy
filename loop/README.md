# loop/ — имплементационный цикл

Автономный цикл: одна итерация = одна задача из [../TASKS.md](../TASKS.md) → зелёный verify → коммит → следующая. Тормоза (итерации, $, отсутствие прогресса) — во внешнем скрипте, не в модели. Результат каждой итерации проверяет отдельная модель-верификатор, не автор.

## Файлы

| Файл | Роль |
|---|---|
| [GOAL.md](GOAL.md) | Контракт: конечное состояние, proof, запреты, бюджет |
| [STATE.md](STATE.md) | Память цикла на диске: статус, журнал, блокеры |
| [ITERATION_PROMPT.md](ITERATION_PROMPT.md) | Промпт рабочей итерации (одна задача, стоп) |
| [VERIFY_PROMPT.MD](VERIFY_PROMPT.md) | Промпт независимого верификатора (read+run, без записи) |
| [run-loop.ps1](run-loop.ps1) | Внешний цикл с тормозами |
| run.log | Журнал запусков (создаётся сам) |

## Шаг 0 — вручную, один раз (обязательно до автоматизации)

1. Инициализировать git и закоммитить текущие документы:

```bash
git init && git add -A && git commit -m "docs: specs, plan, tasks, loop scaffolding"
```

2. **Один ручной прогон итерации** — в интерактивной сессии `claude` дать содержимое `ITERATION_PROMPT.md` и досмотреть T00 до конца. Цель — вскрыть размытые verify и починить их в TASKS.md до автоматизации. Затем вручную прогнать `VERIFY_PROMPT.md` второй сессией и убедиться, что вердикт парсится (`VERDICT: PASS`).

3. Только после этого запускать скрипт.

## Запуск

```bash
powershell -File loop/run-loop.ps1
```

Осторожный режим: `--permission-mode acceptEdits` — правки файлов авто-одобряются, Bash-команды спросят разрешение (цикл будет тормозить на промптах; это нормально для первых прогонов под присмотром).

Полный автоном (лестница, ступень 2+ — только после того, как осторожный режим отработал чисто):

```bash
powershell -File loop/run-loop.ps1 -Autonomous
```

`-Autonomous` включает `--dangerously-skip-permissions`. Запускать только в этой папке-песочнице, при закоммиченном состоянии.

Параметры: `-MaxIterations 25 -MaxCostUsd 15 -MaxNoProgress 3 -VerifierModel sonnet -WorkerModel opus`.

## Тормоза (все снаружи модели)

1. Потолок итераций — 25 (exit 1).
2. Потолок стоимости — $15, сумма `total_cost_usd` из `--output-format json` рабочих и верификаторских вызовов (exit 3). Встроенного лимита $ в Claude Code нет (проверено по docs.claude.com) — поэтому только так.
3. Нет прогресса 3 итерации подряд (ни нового `[x]`, ни нового коммита — считает скрипт по TASKS.md и `git rev-parse HEAD`) → exit 2.
4. Верификатор дал FAIL дважды подряд → exit 4, разбирается человек (см. STATE.md и run.log).

## Лестница автономии (подниматься по одной ступени)

1. **Сейчас:** осторожный режим под присмотром, 2–5 итераций за запуск (`-MaxIterations 5`).
2. Осторожный режим без присмотра на полный лимит.
3. `-Autonomous` под присмотром → без присмотра.
4. По расписанию (Task Scheduler / `/loop` в интерактивной сессии) — **медленное** расписание, 2–3 дня смотреть на run.log, счёт и долю принимаемых коммитов. Если принимается меньше половины — откатиться на ступень ниже.

## Почему внешний скрипт, а не встроенные `/goal`-`/loop`

Сверено с docs.claude.com (актуально на 2026-08): `/goal <condition>` и `/loop [interval]` существуют как built-in и `/goal` работает даже в headless (`claude -p "/goal ..."`), но ни один из них не даёт внешнего потолка стоимости, независимого верификатора другой моделью и детекта прогресса по git — поэтому ядро цикла здесь shell-обёртка над `claude -p --output-format json --max-turns N`. `/goal` можно использовать как облегчённый вариант ВНУТРИ одной задачи (например, «/goal pnpm test exit 0»), но не как замену внешнего цикла.

Перед изменением скрипта перепроверять флаги CLI по первоисточнику: https://code.claude.com/docs/en/cli-reference и /headless — этот слой меняют часто.
